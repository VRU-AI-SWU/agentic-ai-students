Learning objectives

By the end of this episode you will be able to

  1. Explain why a stateless LLM needs memory, and the three ways an agent fails without it
  2. Tell the four memory types apart (working, episodic, semantic, procedural), with examples
  3. Compare RAG-based memory, summaries, knowledge graphs, and MemGPT’s hot / warm / cold tiers
  4. Write a memory store that stores importance and time, retrieves by similarity plus recency, and evicts when full
  5. Let an LLM decide what to remember, whether a memory repeats or contradicts another, forget on request, and reflect failures into lessons
  6. Build an agent that calls its memory through tools, and measure it with memory recall and abstention
  7. Use LangGraph’s checkpointer and Store for memory within and across threads, and keep users apart with namespaces

What did we talk about yesterday?

On Monday the user tells their research assistant they’re writing a report on transformers for time series, and asks for short answers. On Tuesday they come back and ask for new papers. The agent asks which report, then answers in three long paragraphs. This episode answers the question EP11 left: what should an agent remember, and how does it store, retrieve and forget?

Why agents need memory

An LLM is a stateless function: on every call it sees only its context window (Roitman 2026, sec. 17.1). EP07 managed the context within one conversation, but an agent that works for days piles up more than any window can hold (the book’s example: a 128,000-token context against roughly 670,000 tokens for one book). Without memory an agent

  1. forgets context: whatever scrolls out of the window is lost
  2. can’t learn from experience: every task is its first, and mistakes repeat
  3. doesn’t know the user: it starts cold every session

Like a doctor with no patient records: every visit is the first. So the book writes the agent as a cycle: retrieve memory before acting, \(c_t = R(o_t, M)\), act, then write what it learned back, \(M \leftarrow W(M, (o_t, a_t, r_t))\).

Four types of memory

Where memory is kept

  • RAG-based: as in EP10, but the library holds the agent’s own memories. Keep the source and time with every entry: an outdated or wrong memory can produce a confident wrong answer.
  • Summaries: update one summary as information arrives — fixed size, but detail is lost. Store numbers, code and the user’s words verbatim; summarize narratives; discard failed tool calls that carry nothing.
  • Knowledge graphs: facts as (h, r, t); with time intervals you can ask “who was CEO of OpenAI in 2023?”
  • Key-value: retrieved by attention — transformer attention is a special case.
  • MemGPT: tiers, like virtual memory in an operating system: the hot tier in context, the warm tier in a vector store, the cold tier an archive. The agent pages memories in and out by recency, relevance and importance, and the LLM itself calls the search, insert and delete functions (Roitman 2026, sec. 17.3).

The four memory operations

Write. Not everything should be remembered: \(\text{Write}(e) = \mathbb{1}[\text{importance}(e) > \tau]\), scored by surprise, reward, or an LLM rating from 1 to 10. Before writing, check for contradictions, then overwrite, keep both with timestamps, or flag for a human. And the book’s rule: store at the finest grain you can afford and summarize later — facts can always be summarized, but a summary can’t be turned back into facts (Table 17.1).

Read. Combine similarity and recency, \(\text{score} = \lambda \cdot \text{sim}(q, v_d) + (1-\lambda)\,e^{-(t - t_d)/\tau_\text{decay}}\), so a replaced old fact fades.

Update. Consolidate similar memories into one, and forget: LRU (drop what was used longest ago), importance-weighted, or spaced repetition (used often, kept longer).

Reflect. Read from episodic memory, think in working memory, write to semantic memory. The book’s example is Reflexion: three failures become “I keep forgetting to check for an empty list” (Roitman 2026, sec. 17.4).

In Lab 1 a word-for-word copy is skipped (1.00), but “The user wants answers kept brief.” scores 0.94, under the book’s 0.95 threshold, and is stored. Asked about the editor, similarity alone returns both VS Code (0.77) and vim (0.74), which contradict; with recency, two-year-old vim drops out. And on Tuesday, retrieving three, the duplicate takes two slots and the report topic falls out — the model still asks for the topic. Retrieving four, it answers.

In Lab 2 the model rates “Thanks!” 1, “I live in Bangkok” 1 and the deadline 10 (without criteria in the prompt, the deadline swung between 3 and 5). It catches the second request for short answers as a DUPLICATE, turns Friday → Wednesday into an UPDATE that keeps Friday as history, forgets both on request, and reflects three real crashes on [] into one lesson: a new task goes from 0/3 to 3/3.

Across sessions, privacy, and several agents

The book keeps a user model (stated and inferred preferences, expertise, current work) and session continuity in three steps: start the session with the user model and recent session summaries, put them in the system prompt, and end the session by summarizing and updating the model (Roitman 2026, sec. 17.5). On privacy: ask for consent, let users inspect and delete, control access between users, and follow data-retention law.

When several agents work together, a shared blackboard lets them read and write one memory instead of messaging each other, with rules for conflicting writes (last write wins, versions, voting, owners) — more in EP15.

Evaluating memory

LongMemEval splits memory into five abilities: extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention — saying “I don’t know” instead of inventing a memory. Metrics come at three levels: memory (recall, precision, latency, tokens per query), answers (accuracy, faithfulness, contradiction rate) and operations (write selectivity, staleness, storage growth) (Roitman 2026, sec. 17.9).

In Lab 3 a three-tier agent calling memory_search / memory_write itself agreed to keep answers short but never saved it (5 runs out of 5): memory recall below 1 (0.5 in the recording). Automatic extraction from every message, the Mem0 way, reached 1.0, and on Tuesday a new agent that started with a page-in passed all three checks: no PatchTST again, the right deadline, and “I don’t know” for a dog’s name it was never told.

In Lab 4 LangGraph splits a checkpointer (history per thread) from a Store (memory across threads). A new thread starts empty yet answers everything from the Store; a namespace per user keeps Bob away from Alice’s memories; and after store.delete, a new thread no longer knows the deadline while the old thread still answers from its checkpoint — to forget, delete in both places.

Recent advances

  • CoALA: a design language — four memory types, internal and external actions, a decision cycle
  • Mem0: automatic fact extraction, graph memory, merging superseded facts; the book reports +26% relative over OpenAI’s baseline on LOCOMO and more than 90% fewer tokens than full-context approaches
  • Sleep-time compute: use idle time to anticipate questions and precompute — about 5× less test-time compute
  • A-MEM: Zettelkasten notes with keywords, tags and links; new notes can update old ones (Roitman 2026, sec. 17.11)
