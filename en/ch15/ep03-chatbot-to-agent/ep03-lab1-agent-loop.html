▶ Video · ✏️ Starter in Colab · ✅ Solution in Colab · Back to EP03 จาก Chatbot สู่ Agent

Models do not answer the same way every time, so your own run may differ from this page.

In the theory video we saw that an agent is an LLM working in a loop — perceive → reason → act — through tools, with a harness around it. In this lab we build an AI301 course assistant that can answer “how many days until the midterm?” and actually book a tutoring room — all with our own code.

What you’ll learn

  1. chatbot: one model call — it can’t answer and can’t book
  2. tools: calendar, free-room and booking functions + the JSON schemas we give the model
  3. the agent loop: our first harness (loop until done, or until it has to ask a person)
  4. persistence: keep the history in a list, so the conversation can continue across turns
  5. safety: a step limit + a person approves before booking (human-in-the-loop)

The calendar and rooms in this lab are simulated data written for teaching (today = 10 Nov 2026); every model answer and tool call comes from a real run. (The video uses Thai prompts; this English notebook uses English ones, so your outputs will differ in wording.)

Reference: Haggai Roitman, The Hitchhiker’s Guide to Agentic AI, ch15 — CC BY-SA 4.0

1. Calling Gemma through OpenRouter

Why google/gemma-4-26b-a4b-it — follows instructions well and can call tools (tool calling), which is the heart of the agent in this lab and in Lab 2

Why we pin the provider to DeepInfra — Parasail, used in EP02, doesn’t support tools at all. We tested this lab’s agent on 10 providers that support tools (2026-11-10): most took the same steps every time, but one read “this Thursday” as a different day → we pin one provider (deepinfra/fp8) so results repeat

Not free, but very cheap: one full run of the lab ≈ 5,800 tokens ≈ $0.0006 · the :free version doesn’t work (tested 2026-11-15: 6 of 6 calls got 429 “rate-limited upstream”)

FUNCS = {"get_calendar": get_calendar, "find_rooms": find_rooms, "book_room": book_room}

def run_tool(call):
    args = json.loads(call.function.arguments or "{}")
    return json.dumps(FUNCS[call.function.name](**args), ensure_ascii=False)

4. The agent loop = our first harness

In the loop From the theory video
send history + TOOLS to the model 💭 reason
the model asks for a tool → run_tool 🔧 act
the tool’s result goes back into history 👀 perceive (observation)
no more tool requests → answer / ask a person 🏁 done / 🙋 ask a person
max_steps 🛑 guardrail: how many rounds at most

NEEDS_APPROVAL = set()   # part 6 adds the tools that need a person's approval

    return resp.choices[0].message

def run_agent(history, max_steps=MAX_STEPS):
    for step in range(1, max_steps + 1):
        msg = call_llm(history)
        if not msg.tool_calls:
            history.append({"role": "assistant", "content": msg.content})
            return msg.content
        history.append({"role": "assistant", "content": msg.content or "",
                        "tool_calls": [c.model_dump() for c in msg.tool_calls]})
        for call in msg.tool_calls:
            print(f"  🔧 {call.function.name}({call.function.arguments})")
            if call.function.name in NEEDS_APPROVAL:
                PENDING.append(call)
                continue
            result = run_tool(call)
            print(f"  👀 {result}")
            history.append({"role": "tool", "tool_call_id": call.id, "content": result})
        if PENDING:
            return "⏸ waiting for approval"
    return f"⚠️ stopped: reached {max_steps} steps"

6. Safety: guardrails and human-in-the-loop

In part 5 the agent booked at once — correctly this time, but if the model misreads us, a wrong booking is a real consequence. The book says autonomous action needs guardrails and human oversight → the harness enforces it, instead of hoping the model asks

Guardrail in this lab Where
at most MAX_STEPS rounds the loop
book only slots that are really free book_room
book_room needs a person’s approval first NEEDS_APPROVAL + approve()

def approve(history, ok=True):
    while PENDING:
