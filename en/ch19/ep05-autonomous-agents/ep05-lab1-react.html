2. Building Tools

Tool = Python function + JSON schema that tells the model what the tool does and which arguments to send The textbook stresses “Provide good tools” (§19.3): a clear description, a strict schema

TOOLS = {}

def tool(description, properties):
    def wrap(fn):
        TOOLS[fn.__name__] = {"fn": fn, "schema": {"type": "function", "function": {
            "name": fn.__name__,
            "description": description,
            "parameters": {"type": "object", "properties": properties,
                           "required": list(properties), "additionalProperties": False},
        }}}
        return fn
    return wrap

def schemas(names):
    return [TOOLS[n]["schema"] for n in names]

def react_agent(task, tool_names, max_iterations=10):
    messages = [{"role": "user", "content": task}]
    for i in range(1, max_iterations + 1):           # ③ max iterations
        msg = ask_llm(messages, tools=schemas(tool_names))
        thought = getattr(msg, "reasoning", None)    # ① scratchpad
        if thought:
            print(f"💭 [{i}]", thought[:200])
        calls = msg.tool_calls or []                 # ② tool parsing
        if not calls:                                # ④ termination
            return msg.content
        messages.append({"role": "assistant", "content": msg.content or "",
                         "tool_calls": [c.model_dump() for c in calls]})
        for c in calls:
            print(f"🔧 [{i}] {c.function.name}({c.function.arguments})")
        with ThreadPoolExecutor() as pool:
            results = list(pool.map(run_tool, calls))
        for r in results:
            print(f"👀 [{i}]", r["content"][:150])
        messages.extend(results)
    return "⚠️ Stopped: reached max_iterations"

✅ Based on the models researched, here are the three key ways they differ in their approach to time-series forecasting:

* **Attention Target (Time vs. Variates):** While standard transformers focus on temporal dependencies, **iTransformer** reverses this by applying attention across different variables (variates) rather than time steps, treating the entire time series of a single variable as a token.
* **Dimensionality Handling:** **PatchTST** employs "channel independence," treating each variable as an isolated sequence to simplify the task, whereas **Crossformer** uses a "two-stage attention" mechanism to explicitly model complex dependencies across different dimensions.
* **Temporal Representation:** **PatchTST** breaks time series into local "patches" to capture semantic information and reduce complexity, whereas **iTransformer** preserves the full temporal profile of a variable within a single high-dimensional embedding.
