From workflow to agent

In EP04 (§19.1) we studied workflow patterns, where the program — not the model — sets the order of work. The autonomous agent patterns in this section let the LLM control the execution flow itself: which tool to call, when, and when to stop (Roitman 2026, sec. 19.2).

ImportantAlways start with a workflow

The textbook recommends an agent only when the task genuinely needs dynamic routing or open-ended exploration.

ReAct (Reason + Act)

ReAct (Yao et al. 2023) is the basic pattern behind almost every agent. The LLM alternates between a Thought (what to do), an Action (call a tool) and an Observation (read the result), looping until it has a final answer.

\[ \text{Thought}_t \rightarrow \text{Action}_t \rightarrow \text{Observation}_t \rightarrow \text{Thought}_{t+1} \rightarrow \cdots \tag{5.1}\]

The harness around the ReAct loop (Figure 5.1) needs four things:

  1. Scratchpad — Thought steps are logged but not shown to the user
  2. Tool parsing — structured tool calls are extracted from the model’s output
  3. Max iterations — always cap the number of loops (typically 10–25)
  4. Termination — stop when the model emits a special action such as final_answer, or makes no tool call

In Lab 1: we write react_agent() with all four, and see that with max_iterations=1 the agent stops at once.

Planning Agents

ReAct decides one step at a time, which can wander on long tasks. A planning agent first builds an explicit plan, then executes it and revises it along the way. Chapter 18 calls this Plan-and-Execute, with three phases: planning, execution (possibly with a cheaper model) and plan revision.

\[ \text{Plan} = \text{Planner}(q), \qquad \text{Result} = \prod_{i=1}^{|\text{Plan}|} \text{Executor}(\text{Plan}[i], \text{context}_i) \tag{5.2}\]

Example: a report comparing transformers for time series

The user asks: “Write a 2-page report comparing transformer architectures for time-series forecasting.” The planner writes a 6-step plan; each step lists in deps the steps that must finish first, so the plan is a DAG (Directed Acyclic Graph), as in Figure 5.2.

The harness tracks dependencies and executes only the steps whose prerequisites are all done.

Adaptive replanning

After step 1, the search finds only 3 relevant papers, so the agent replans: it adds a sub-step that widens the search to neighbouring work (e.g. PatchTST, iTransformer), then continues from step 2 with more material.

NoteKey insight

A plan is a living document — it gives structure, but adapts to what the agent observes.

In Lab 2: the Adaptive strategy: when the search step finds only 3 papers, the harness replans, and each step runs react_agent() from Lab 1, so patterns compose.

Reflection and Self-Critique

An agent stops to evaluate its own path at three levels:

  1. Output validation — “Is this right? Did I miss anything?”
  2. Trajectory review — look back over the last k steps for mistakes or waste
  3. Strategy revision — “Am I solving the right problem?”

Reflexion

Reflexion (Shinn et al. 2023) keeps a reflection memory. After each failure, the agent writes a lesson in natural language (e.g. “I failed because I didn’t check the edge case”) and puts these lessons in the next attempt’s prompt — so it learns across episodes without updating any weights.

In Lab 3: the agent writes parse_duration(), checked by unit tests it can’t see in advance. In the recorded run the first attempt passed 5/9, and after one lesson all 9/9.

Tool-Use Patterns

Things to remember:

  • Multi-tool cuts latency a lot, but the tools must be independent, and all tool results go back in a single message
  • Sequential: the harness must manage the growing context, and may need to summarize along the way
  • Nested: the parent agent sees the sub-agent as a black-box function
  • Fallback is handled in the harness; the model doesn’t need to know

In Lab 4: single-turn takes exactly 2 LLM calls, and three tools that take 1.5 s each finish in ~1.5 s in parallel instead of 4.5 s.

Which pattern to choose

Start with the simplest pattern and move up only when the simpler one genuinely isn’t enough — and patterns compose.

From your own code to LangGraph

In Lab 5 we rebuild the agents from Labs 1 and 2 with LangGraph. Every piece of the framework maps to code we already wrote.

What the framework adds is a checkpoint that saves the state at every step, so the graph can pause for human approval before a tool runs (human-in-the-loop), resume, and let you look back at any step.

Further reading

  • Overview: the most-cited introduction to agents — planning, memory, tool use (Weng 2023) — and a full survey (Wang et al. 2024)
  • ReAct: the original paper (Yao et al. 2023)
  • Planning: plan before acting (Plan-and-Solve) (Wang et al. 2023), separate planning from tool results to save tokens (ReWOO) (Xu et al. 2023), and DAG plans with parallel tool calls (LLMCompiler) (Kim et al. 2024)
  • Reflexion: the original paper (Shinn et al. 2023)
  • Tool use: a model that learns when to call tools (Toolformer) (Schick et al. 2023) and practical advice on designing tools for agents (Anthropic 2025)
