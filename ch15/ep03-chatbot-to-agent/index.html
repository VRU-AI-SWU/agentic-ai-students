วัตถุประสงค์การเรียนรู้

เมื่อจบตอนนี้ ผู้เรียนจะสามารถ

  1. อธิบายความต่างระหว่าง chatbot ที่ตอบครั้งเดียวกับ agent ที่ทำงานเป็นวง รับรู้ คิด ลงมือ
  2. อธิบายว่า model ลงมือผ่าน tool ได้อย่างไร ทั้งที่มันเขียนได้แค่ข้อความ
  3. บอกหน้าที่ของ harness และเขียน agent loop เองด้วย Python
  4. อธิบายห้าความท้าทายของ agent (persistence, grounding, action, coordination, safety) และชี้ได้ว่าแต่ละข้ออยู่ตรงไหนในโค้ด
  5. ใส่ guardrail และให้คนอนุมัติก่อน agent ลงมือในเรื่องที่สำคัญ
  6. จับคู่แต่ละชิ้นของ LangChain (@tool, create_agent, checkpointer, middleware) กับโค้ดที่เขียนเอง

คำขอที่ chatbot ทำไม่ได้

สมมติว่านักศึกษาพิมพ์มาว่า “อีกกี่วันจะสอบกลางภาค ช่วยจองห้องติวให้หน่อย” chatbot ที่เก่งแค่ไหนก็มักตอบได้แค่ว่า ขออภัย ไม่ทราบวันที่วันนี้ และจองห้องให้ไม่ได้ แล้วก็หยุดรอ ส่วนผู้ช่วยอีกแบบเปิดปฏิทินเอง ดูว่าห้องไหนว่าง ถามเราก่อนว่าจองห้องนี้ได้ไหม แล้วจองให้จริง ทั้งสองแบบใช้ model ตัวเดียวกันได้ สิ่งที่ต่างคือสิ่งที่เราสร้างไว้รอบ model

Chatbot: ตอบหนึ่งครั้ง แล้วรอ

ตำราเรียกสิ่งที่เราใช้กันทุกวันว่า chatbot แบบตอบรอบเดียว (single-turn chatbot): model ได้ข้อความหนึ่งข้อความ ตอบกลับหนึ่งคำตอบ แล้วหยุดรอ (Roitman 2026, ch. 15) เหมือนรุ่นพี่ที่เราโทรไปถาม บอกได้ว่าควรทำอะไร เข้าเว็บไหน แต่ลงมือทำแทนเราไม่ได้ และสิ่งที่รุ่นพี่คนนี้รู้ก็มีแค่สิ่งที่เรียนมาตอนฝึก จาก EP01 เรารู้แล้วว่า model ไม่รู้ว่าวันนี้วันที่เท่าไร และไม่เคยเห็นปฏิทินสอบของวิชาเรา

ใน Lab 1: เรียก Gemma ครั้งเดียวด้วยคำขอนี้ model บอกเองว่าไม่รู้วันสอบของเรา และเข้าระบบจองห้องไม่ได้

Agent: LLM ที่ทำงานเป็นวง

ตำรานิยามระบบ agentic AI ว่าเป็นระบบที่ LLM ทำงานเป็นวง รับสิ่งที่เห็นจากสภาพแวดล้อม คิดว่าจะทำอะไรต่อ แล้วลงมือ วนไปจนบรรลุเป้าหมาย หรือจนกว่าจะหยุดถามคน (Roitman 2026, ch. 15) สิ่งที่เห็นในแต่ละรอบเรียกว่า observation อาจเป็นข้อความของผู้ใช้ ผลลัพธ์จาก tool หรือข้อมูลจากเซนเซอร์ ส่วนการลงมืออาจเป็นการเรียก tool รันโค้ด หรือเรียก API แนวคิดให้ model คิดสลับกับลงมือนี้ตรงกับ ReAct ที่เราจะเจออีกใน EP05 (Yao และคณะ 2023)

ลองนึกถึงเลขาที่ได้รับงานจัดห้องติว:

ขั้นต่อไปของทุกรอบมาจากสิ่งที่เพิ่งเห็นในรอบก่อน นี่คือสิ่งที่การเรียก model ครั้งเดียวทำไม่ได้

Tool: model ขอ โปรแกรมทำ

model เขียนได้แค่ข้อความ มันกดปุ่มจองห้องเองไม่ได้ คำตอบคือ tool ซึ่งก็คือฟังก์ชันในโปรแกรมของเราเอง เช่นเปิดปฏิทิน ดูห้องว่าง และจองห้อง เราบอก model ว่ามีเครื่องมืออะไรให้ใช้ เมื่อมันอยากใช้ มันจะเขียนคำขอออกมาเป็นแบบฟอร์มที่เรียกว่า tool call ว่าอยากเรียกเครื่องมือไหน ด้วยค่าอะไร (Schick และคณะ 2023) แล้วโปรแกรมของเราเป็นคนเรียกฟังก์ชันนั้นจริง ผลที่ได้ส่งกลับไปเป็น observation ของรอบถัดไป เหมือนหมอที่เขียนใบสั่งยา แต่คนจ่ายยาคือเภสัชกร

ใน Lab 1 “เภสัชกร” คือฟังก์ชันสามบรรทัดนี้:

def run_tool(call):
    args = json.loads(call.function.arguments or "{}")
    return json.dumps(FUNCS[call.function.name](**args), ensure_ascii=False)

Harness: ตัวรถรอบเครื่องยนต์

ใครเป็นคนวนรอบ ใครเรียก tool ใครเก็บว่าทำอะไรไปแล้ว ตำราเรียกส่วนนี้ว่า harness และเปรียบว่าเป็นระบบปฏิบัติการของ agent: คุมวงของ agent ดูแลงบของ context window ส่งงานให้ tool จัดการเมื่อมีอะไรพัง เก็บสถานะ และบันทึกให้ย้อนดูได้ว่า agent ทำอะไรไปบ้าง (Roitman 2026, ch. 15) ถ้า model คือเครื่องยนต์ harness ก็คือรถทั้งคัน ทั้งพวงมาลัย เบรก และเข็มขัดนิรภัย เครื่องยนต์แรงแค่ไหนก็พาเราไปไม่ถึงไหนถ้าไม่มีตัวรถ

harness ตัวแรกของเราใน Lab 1 คือลูปนี้:

def run_agent(history, max_steps=MAX_STEPS):
    for step in range(1, max_steps + 1):
        msg = call_llm(history)
        if not msg.tool_calls:                      # ไม่ขอ tool แล้ว = ตอบเสร็จ
            history.append({"role": "assistant", "content": msg.content})
            return msg.content
        history.append({"role": "assistant", "content": msg.content or "",
                        "tool_calls": [c.model_dump() for c in msg.tool_calls]})
        for call in msg.tool_calls:
            if call.function.name in NEEDS_APPROVAL:  # เรื่องสำคัญ: พักไว้รอคน
                PENDING.append(call)
                continue
            result = run_tool(call)
            history.append({"role": "tool", "tool_call_id": call.id, "content": result})
        if PENDING:
            return "⏸ รออนุมัติ"
    return f"⚠️ หยุด: ครบ {max_steps} รอบ"

ใน Lab 1: พอเติม tool สามตัวกับลูปนี้ agent เรียก get_calendar เห็นว่าวันนี้วันอังคารที่ 10 คิดเองว่าพฤหัสนี้คือวันที่ 12 แล้วเรียก find_rooms สุดท้ายตอบว่าอีกแปดวันสอบ และเพราะห้อง 3 ว่างทั้งบ่ายโมงและบ่ายสาม มันจึงไม่เดาเอง แต่ถามเรากลับ

ห้าความท้าทายของ agent

เมื่อเปลี่ยนจาก chatbot มาเป็น agent ตำราบอกว่าเราจะเจอความท้าทายพื้นฐานห้าข้อ ที่การเรียก model ครั้งเดียวแก้ไม่ได้ (Roitman 2026, ch. 15)

Persistence สำคัญเพราะ model เองไม่จำอะไรข้ามการเรียกเลย ทุกครั้งที่เรียก มันเห็นแค่สิ่งที่อยู่ใน context window ตอนนั้น การจำจึงเป็นหน้าที่ของ harness ที่ต้องเก็บประวัติแล้วส่งกลับเข้าไปทุกครั้ง เหมือนเลขาที่ความจำหายทุกเช้า แต่มีสมุดบันทึกไว้เปิดดู ส่วน action ตำราเปรียบมาตรฐานการต่อ tool ว่าเหมือนพอร์ต USB ต่อแบบเดียว ใช้ได้กับทุกอุปกรณ์ ซึ่งคือ MCP ใน EP13

ใน Lab 1: ตอบ “13:00 ครับ” ต่อในประวัติเดิม agent จองห้อง 3 วันที่ 12 บ่ายโมงได้ถูกต้อง แต่พอเริ่มประวัติใหม่แล้วขอเลื่อนเป็นบ่ายสาม มันถามกลับว่าวันไหน ห้องไหน ความจำของ agent จึงไม่ได้อยู่ใน model แต่อยู่ในประวัติที่ harness เก็บ

Safety: guardrail และ human-in-the-loop

ข้อสุดท้ายสำคัญที่สุดเมื่อ agent ลงมือได้จริง ตำราบอกว่าการกระทำที่เป็นอิสระต้องมีสามอย่าง: guardrail กติกาที่ harness บังคับ เช่นจองได้แค่ห้องติวและวนได้ไม่เกินแปดรอบ, การให้คนกำกับดูแลหรือ human-in-the-loop เหมือนเด็กฝึกงานที่ต้องให้หัวหน้าเซ็นก่อนจ่ายเงิน และเมื่อไม่แน่ใจต้องถอยอย่างนุ่มนวล บอกตรงๆ หรือถามคน ดีกว่าแต่งเรื่องว่าจองให้แล้ว ทั้งที่ยังไม่ได้จอง

ใน Lab 1 มี guardrail สามชั้น:

  • จำกัดรอบ: max_steps=1 agent เรียกปฏิทินได้ครั้งเดียวแล้วหยุด “ครบ 1 รอบ”
  • ตรวจในตัว tool: book_room ตรวจก่อนว่าห้องว่างจริงตอนนั้น ถ้าไม่ว่างคืน error แทนการจองมั่ว
  • ขออนุมัติ: ใส่ book_room ใน NEEDS_APPROVAL แล้วขอเลื่อนเป็นบ่ายสาม harness พักคำขอไว้ การจองยังเป็นบ่ายโมงจนเรากดอนุมัติ จึงเปลี่ยนเป็นบ่ายสาม

Agentic AI stack: แผนที่ของทั้งซีรีส์

ตำราไม่มอง agent เป็น model ตัวเดียว แต่เป็นระบบหลายชั้น แต่ละชั้นแก้ปัญหาหนึ่งเรื่อง (Roitman 2026, Figure 15.1) ภาพนี้คือแผนที่ของทั้งซีรีส์เราด้วย และทุกชั้นจะถูกเพิ่มเข้าไปในโปรเจกต์เดียวกัน คือผู้ช่วยค้นคว้างานวิจัย (Research Assistant Agent)

ตรงกลางคือ agent core ล้อมด้วย harness ที่ตัดสินว่าเมื่อไรจะค้นข้อมูล เมื่อไรจะเรียก tool เมื่อไรจะส่งงานให้ agent ตัวอื่น และเมื่อไรจะถามคน ด้านล่างคือสิ่งที่ agent ต่อออกไป ด้านบนคือผู้ใช้ที่ให้เป้าหมาย feedback และคอยกำกับ ส่วน design pattern (EP04–06) การวัดผล (EP17–18) และ framework (EP19) มีตอนของมันเอง ตำราสรุปว่า agentic AI ไม่ใช่แค่การเขียน prompt แต่ต้องออกแบบการจัดการ context การรับมือ error guardrail และการสังเกตการทำงานในทุกชั้น

เขียนเอง vs framework

Lab 2 สร้างผู้ช่วยตัวเดิมอีกครั้งด้วย LangChain แล้วเทียบทีละชิ้น ตำรามีตารางเทียบ framework ไว้ในบทที่ 18 (Roitman 2026, Table 18.1) ส่วนตารางข้างล่างคือสิ่งที่เราเห็นจริงในสอง lab

safe = create_agent(llm, tools=TOOLS, system_prompt=SYSTEM, checkpointer=memory,
                    middleware=[HumanInTheLoopMiddleware(interrupt_on={"book_room": True})])
config = {"configurable": {"thread_id": "student-1"}}
safe.invoke({"messages": [{"role": "user", "content": "ขอเลื่อนเป็นบ่ายสามได้ไหม"}]}, config)  # ⏸ พักไว้
safe.invoke(Command(resume={"decisions": [{"type": "approve"}]}), config)                   # ✅ จองจริง

ใน Lab 2: agent เดินขั้นตอนเหมือน Lab 1 ทุกขั้น ข้างในเก็บประวัติแบบเดียวกัน (human, ai, tool, ai, tool, ai) แต่ framework ไม่ได้จำให้เอง: ไม่ใส่ checkpointer แล้วตอบ “13:00 ครับ” ไม่มีการจองเลย พอใส่ checkpointer จึงจองได้ใน thread student-1 ส่วน thread student-2 ถามกลับว่าวันไหน ห้องไหน ModelCallLimitMiddleware(run_limit=1) หยุดหลังเรียกปฏิทินครั้งเดียว และ HumanInTheLoopMiddleware พัก book_room ไว้ การจองยังเป็นบ่ายโมงจนเราส่ง "approve" กลับไป จึงเปลี่ยนเป็นบ่ายสาม

framework ช่วยให้โค้ดสั้นลงและมีของพร้อมใช้ เช่นเก็บประวัติลงฐานข้อมูล หรือไม่อนุมัติพร้อมเหตุผล แต่ทุกชิ้นคือสิ่งที่เราเขียนเองได้ใน Lab 1 และเมื่อ agent ทำตัวแปลกๆ ความเข้าใจจาก Lab 1 คือสิ่งที่ช่วยให้รู้ว่าต้องดูตรงไหน

ให้ model คิด ให้ tool ลงมือ และให้คนตัดสินใจในเรื่องที่สำคัญ

ปฏิทินและระบบจองห้องเป็นข้อมูลจำลองเพื่อการสอน ส่วน output ของ model ในวิดีโอมาจากการรันจริง คำตอบที่คุณรันเองจึงอาจต่างไปบ้าง เช่นถ้อยคำที่ agent ใช้ถามกลับ

คำถามทบทวน

  1. chatbot แบบตอบรอบเดียวกับ agent ต่างกันอย่างไร ยกตัวอย่างจากคำขอจองห้องติว
  2. model เขียนได้แค่ข้อความ แล้ว agent จองห้องได้อย่างไร ใครเป็นคนรันฟังก์ชันจริง
  3. harness ทำหน้าที่อะไรบ้าง และใน Lab 1 harness ของเราคือโค้ดส่วนไหน
  4. ทำไมใน Lab 1 agent จึงถามกลับแทนที่จะจองห้องทันที
  5. เมื่อเริ่มประวัติใหม่แล้วขอเลื่อนการจอง agent ทำอะไร และนั่นบอกอะไรเกี่ยวกับความจำของ agent
  6. guardrail สามชั้นใน Lab 1 คืออะไร และแต่ละชั้นอยู่ที่ไหนในโค้ด

อ่านเพิ่มเติม

ไม่จำเป็นต่อการทำ lab แต่ช่วยให้เข้าใจลึกขึ้น

  • Agent ภาพรวม: บทความภาพรวมของ LLM agent (Weng 2023) และ survey (Wang และคณะ 2024)
  • Agent loop: ReAct ที่ให้ model คิดสลับกับลงมือ (Yao และคณะ 2023)
  • Tool use: model ที่เรียนรู้การเรียก tool เอง (Schick และคณะ 2023) และแนวทางเขียน tool ให้ agent (Anthropic 2025)
  • ออกแบบ agent ให้เรียบง่าย: เมื่อไรควรใช้ agent และเมื่อไร workflow ก็พอ (Schluntz และ Zhang 2024) ซึ่งเป็นคำถามของ EP04
