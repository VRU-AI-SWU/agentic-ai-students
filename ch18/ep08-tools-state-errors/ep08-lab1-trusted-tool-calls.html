  1. นิยาม tool แบบ OpenAI (parameters = JSON schema) แล้วให้ model ขอ paper สามเรื่องในรอบเดียว (parallel tool calls)

paper, หน้าเว็บ และเวลาที่ tool ใช้ เป็น ข้อมูลจำลองที่เขียนขึ้นเพื่อการสอน ส่วน tool call, คำตอบ และจำนวนรอบที่โดน injection มาจากการรันจริง

1. เรียก Gemma ผ่าน OpenRouter

ทำไมใช้ google/gemma-4-26b-a4b-it — เรียก tool ได้ และ ขอหลาย tool ในรอบเดียวได้ (parallel tool calls) ซึ่ง lab นี้ต้องใช้ tokenizer ก็เปิดให้โหลด เราจึงนับ token บนเครื่องได้ตรงกับที่ model นับ (EP07)

ทำไมล็อก provider เป็น Makora (ไม่ใช่ DeepInfra เหมือน EP07) — เราทดสอบทุกเจ้าที่ให้บริการ Gemma 4 ตัวนี้ (2026-11-17): Makora เป็นเจ้าเดียวที่ รายงาน cached_tokens ได้สม่ำเสมอ ซึ่ง Lab 4 ต้องใช้ดู prompt caching และขอ tool สามตัวในรอบเดียวได้ทุกครั้ง · ทั้ง EP ใช้เจ้าเดียวกัน ผลจะได้เทียบกันได้

ไม่ฟรี แต่ถูกมาก: Makora คิด 0.09 ดอลลาร์ต่อล้าน token ขาเข้า และ 0.28 ต่อล้าน token ขาออก — ท้าย lab เราจะรวมค่าใช้จ่ายจริงให้ดู · รุ่น :free ใช้ไม่ได้ (ทดสอบ 2026-11-17: 3 ใน 3 ครั้งได้ 429 “rate-limited upstream”)

import json, os, time
from concurrent.futures import ThreadPoolExecutor
from openai import OpenAI

def load_key():
    try:  # Google Colab Secrets
        from google.colab import userdata
        return userdata.get("OPENROUTER_API_KEY")
    except ImportError:
        pass
    from dotenv import load_dotenv
    load_dotenv()
    return os.environ["OPENROUTER_API_KEY"]

client = OpenAI(base_url="https://openrouter.ai/api/v1", api_key=load_key())
MODEL = "google/gemma-4-26b-a4b-it"
PROVIDER = {"order": ["makora"], "allow_fallbacks": False}
EXTRA = {"reasoning": {"enabled": False}, "provider": PROVIDER}

USAGE = {"in": 0, "out": 0}

def chat(messages, **kw):
    reply = client.chat.completions.create(model=MODEL, messages=messages, extra_body=EXTRA, **kw)
    USAGE["in"] += reply.usage.prompt_tokens
    USAGE["out"] += reply.usage.completion_tokens
    return reply.choices[0].message

### Summary of PatchTST (2023) Project Page

**Core Methodology**
PatchTST is a time-series forecasting model that utilizes a "patching" mechanism. Instead of processing individual time steps, the model splits each series into **patches of 16 steps**. Additionally, the architecture is designed to handle each channel within a multivariate series independently.

**Performance Overview**
The provided data contains extensive error metrics across several datasets (ETTh1, ETTh2, ETTh3, and ETTh4) at various forecasting horizons (96, 192, 288, and 384). The results are reported using two primary error measurements:
*   **MSE** (Mean Squared Error)
*   **MAE** (Mean Absolute Error)

**Key Data Observations**
