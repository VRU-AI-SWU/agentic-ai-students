EP12 Agent Memory

ch.17 · ความจำสี่ชนิด · MemGPT · เขียน อ่าน อัปเดต ลืม ทบทวน · ความจำข้าม session · วัดผลความจำ

วัตถุประสงค์การเรียนรู้

เมื่อจบตอนนี้ ผู้เรียนจะสามารถ

  1. อธิบายว่าทำไม LLM ที่ไม่มีสถานะต้องมีความจำ และสามแบบที่ agent พังเมื่อไม่มี
  2. แยกความจำสี่ชนิด (working, episodic, semantic, procedural) พร้อมตัวอย่าง
  3. เปรียบเทียบที่เก็บความจำแบบ RAG, สรุป, กราฟความรู้ และชั้นร้อน อุ่น เย็นของ MemGPT
  4. เขียนคลังความจำที่เก็บพร้อมความสำคัญและเวลา ค้นด้วยความเหมือนบวกความใหม่ และลบเมื่อเต็ม
  5. ให้ LLM ช่วยตัดสินว่าอะไรควรจำ ความจำซ้ำหรือขัดกัน ลืมเมื่อผู้ใช้ขอ และทบทวนความล้มเหลวเป็นบทเรียน
  6. สร้าง agent ที่เรียกความจำเองผ่าน tool และวัดด้วย memory recall และ abstention
  7. ใช้ checkpointer และ Store ของ LangGraph แยกความจำใน thread กับความจำข้าม thread และแยกผู้ใช้ด้วย namespace

เมื่อวานเราคุยอะไรกัน

วันจันทร์ผู้ใช้บอก research assistant ว่ากำลังเขียนรายงานเรื่อง transformer สำหรับ time series และขอคำตอบสั้นๆ วันอังคารกลับมาถามว่ามี paper ใหม่ไหม agent ถามกลับว่ารายงานไหน แล้วตอบยาวสามย่อหน้า ตอนนี้ตอบคำถามที่ EP11 ทิ้งไว้: agent ควรจำอะไร และเก็บ ค้น และลืมอย่างไร

ทำไม agent ต้องมีความจำ

LLM เป็นฟังก์ชันที่ไม่มีสถานะ ทุกครั้งที่เรียก มันเห็นแค่ context window (Roitman 2026, หมวด 17.1) EP07 จัดการ context ในบทสนทนาเดียว แต่ agent ที่ทำงานหลายวันสะสมข้อมูลมากกว่าที่หน้าต่างไหนจะจุได้ (ตำรายกตัวอย่าง context 128,000 token เทียบหนังสือหนึ่งเล่มราว 670,000 token) ถ้าไม่มีความจำ agent จะ

  1. ลืมบริบท: สิ่งที่เลื่อนออกจากหน้าต่างหายไปเลย
  2. เรียนรู้จากประสบการณ์ไม่ได้: ทุกงานเหมือนครั้งแรก ทำผิดซ้ำ
  3. ไม่รู้จักผู้ใช้: เริ่มใหม่ทุก session

เหมือนหมอที่ไม่มีแฟ้มประวัติคนไข้ ทุกครั้งที่ไปหาคือครั้งแรก ตำราจึงเขียน agent เป็นวงจร: ค้นความจำก่อนทำ \(c_t = R(o_t, M)\) ทำ แล้วเขียนสิ่งที่เรียนรู้กลับไป \(M \leftarrow W(M, (o_t, a_t, r_t))\)

ความจำสี่ชนิด

เก็บไว้ที่ไหน

  • RAG-based: แบบ EP10 แต่สิ่งที่อยู่ในคลังคือความจำของ agent เอง ต้องเก็บแหล่งที่มาและเวลาไว้กับทุกชิ้น เพราะความจำที่เก่าหรือผิดทำให้ตอบผิดอย่างมั่นใจได้
  • สรุป: อัปเดตสรุปเดิมทุกครั้งที่มีข้อมูลใหม่ ขนาดคงที่แต่รายละเอียดหาย ตัวเลข โค้ด และคำพูดของผู้ใช้ให้เก็บคำต่อคำ เรื่องเล่าสรุปได้ tool ที่ล้มเหลวโดยไม่ได้ข้อมูลอะไรให้ทิ้ง
  • กราฟความรู้: เก็บเป็น (h, r, t) ถ้าใส่ช่วงเวลา ก็ถามได้ว่า “ใครเป็น CEO ของ OpenAI ในปี 2023”
  • Key-value: ค้นด้วย attention ซึ่ง attention ใน transformer เป็นกรณีพิเศษของแบบนี้
  • MemGPT: แบ่งความจำเป็นชั้นเหมือน virtual memory ของระบบปฏิบัติการ ชั้นร้อนอยู่ใน context ชั้นอุ่นอยู่ใน vector store ชั้นเย็นคือ archive agent ย้ายของเข้า (page-in) และออก (page-out) ตามความใหม่ ความเกี่ยว และความสำคัญ และตัว LLM เองเป็นคนเรียก function ค้น เพิ่ม ลบ (Roitman 2026, หมวด 17.3)

สี่งานของความจำ

Write. ไม่ใช่ทุกอย่างควรถูกจำ \(\text{Write}(e) = \mathbb{1}[\text{importance}(e) > \tau]\) คะแนนมาจากความไม่คาดคิด รางวัล หรือให้ LLM ให้คะแนน 1–10 ก่อนเขียนต้องตรวจว่าขัดกับของเก่าไหม แล้วเลือกจะเขียนทับ เก็บทั้งคู่พร้อมเวลา หรือส่งให้คนตัดสิน และตำราให้หลักว่า เก็บละเอียดที่สุดเท่าที่จ่ายไหว แล้วค่อยสรุป เพราะสรุปจากข้อเท็จจริงได้เสมอ แต่ย้อนจากสรุปกลับไปไม่ได้ (Table 17.1)

Read. คะแนนรวมความเหมือนกับความใหม่ \(\text{score} = \lambda \cdot \text{sim}(q, v_d) + (1-\lambda)\,e^{-(t - t_d)/\tau_\text{decay}}\) ความจำเก่าที่ถูกแทนที่แล้วจะจางลง

Update. รวมความจำที่คล้ายกันเป็นชิ้นเดียว และลืม: LRU (ลบชิ้นที่ไม่ได้ใช้นานที่สุด) ลืมตามความสำคัญ หรือ spaced repetition (ใช้บ่อย อยู่นาน)

Reflect. อ่านจาก episodic คิดใน working แล้วเขียนเป็น semantic ตำรายกตัวอย่าง Reflexion: ล้มเหลวสามครั้ง ได้บทเรียนว่า “ฉันลืมเช็ก list ว่างทุกครั้ง” (Roitman 2026, หมวด 17.4)

ใน Lab 1 ประโยคที่ซ้ำคำต่อคำถูกข้าม (1.00) แต่ “The user wants answers kept brief.” ได้ 0.94 ต่ำกว่าเกณฑ์ 0.95 ของตำราจึงถูกเก็บ ถามเรื่อง editor ความเหมือนอย่างเดียวได้ทั้ง VS Code 0.77 และ vim 0.74 ที่ขัดกัน พอบวกความใหม่ vim ที่เก่าสองปีก็หลุด และวันอังคารที่ค้นสามชิ้น ความจำซ้ำกินสองช่อง หัวข้อรายงานหลุด model ยังถามหัวข้อ ค้นสี่ชิ้นถึงตอบได้

ใน Lab 2 model ให้คะแนน “Thanks!” 1, “I live in Bangkok” 1, กำหนดส่ง 10 (ถ้าไม่บอกเกณฑ์ใน prompt คะแนนกำหนดส่งแกว่ง 3–5) จับคำขอคำตอบสั้นครั้งที่สองเป็น DUPLICATE กำหนดส่งที่เลื่อนจากวันศุกร์เป็นวันพุธเป็น UPDATE โดยเก็บวันศุกร์เป็นประวัติ ลืมได้ทั้งปัจจุบันและประวัติเมื่อผู้ใช้ขอ และฟังก์ชันที่ model เขียนพังกับ [] สามครั้ง ทบทวนได้บทเรียนเดียว งานใหม่จากพัง 0/3 เป็นผ่าน 3/3

ความจำข้าม session ความเป็นส่วนตัว และหลาย agent

ตำราให้เก็บแฟ้มผู้ใช้ (ความชอบที่บอก ความชอบที่เดาจากพฤติกรรม ระดับความรู้ งานที่ทำ) แล้ว session continuity สามขั้น: เริ่ม session ด้วยแฟ้มและสรุปของ session ก่อน ใส่ใน system prompt และจบ session ด้วยการสรุปแล้วอัปเดตแฟ้ม (Roitman 2026, หมวด 17.5) ความเป็นส่วนตัว: ต้องขอความยินยอม ให้ผู้ใช้ดูและลบได้ คุมสิทธิ์ระหว่างผู้ใช้ และทำตามกฎหมายเก็บข้อมูล

เมื่อหลาย agent ทำงานด้วยกัน ความจำกลางแบบ blackboard ให้ทุกตัวอ่านและเขียนแทนการส่งข้อความหากัน และต้องมีกติกาเมื่อเขียนขัดกัน (ใครเขียนทีหลังชนะ เก็บทุกเวอร์ชัน โหวต กำหนดเจ้าของ) — ลงลึกใน EP15

วัดผลความจำ

LongMemEval แบ่งความสามารถเป็นห้าข้อ: ดึงข้อเท็จจริงได้ โยงข้าม session ได้ แยกเวลาได้ ตามทันเมื่อข้อมูลเปลี่ยน และ abstention กล้าตอบว่าไม่รู้แทนการแต่งความจำ metric มีระดับความจำ (memory recall, precision, latency, token ต่อคำถาม) ระดับคำตอบ (ความถูกต้อง faithfulness อัตราขัดแย้ง) และระดับการทำงาน (เขียนบ่อยแค่ไหน ดึงของเก่ามาบ่อยไหม ความจำโตเร็วแค่ไหน) (Roitman 2026, หมวด 17.9)

ใน Lab 3 agent สามชั้นที่เรียก memory_search / memory_write เอง รับปากว่าจะตอบสั้นแต่ไม่บันทึกเลย (5 ใน 5 รอบ) memory recall ไม่ถึง 1 (รอบที่อัดได้ 0.5) ดึงอัตโนมัติจากทุกข้อความแบบ Mem0 ได้ 1.0 และวันอังคาร agent ตัวใหม่ที่เริ่มด้วย page-in ผ่านทั้งสามข้อ: ไม่แนะนำ PatchTST ซ้ำ บอกกำหนดส่งถูก และตอบว่าไม่รู้ชื่อสุนัขที่ไม่เคยถูกบอก

ใน Lab 4 LangGraph แยก checkpointer (history ต่อ thread) กับ Store (ความจำข้าม thread) thread ใหม่เริ่มว่างแต่ตอบได้ครบจาก Store namespace ต่อผู้ใช้ทำให้บ็อบไม่เห็นความจำของอลิซ และหลัง store.delete thread ใหม่ไม่รู้กำหนดส่งแล้ว แต่ thread เดิมยังตอบจาก checkpoint — จะลืมให้หมดต้องลบทั้งสองที่

งานใหม่

  • CoALA: ภาษาออกแบบ แยก agent เป็นความจำสี่ชนิด action ภายใน/ภายนอก และวงจรตัดสินใจ
  • Mem0: ดึงข้อเท็จจริงอัตโนมัติ โยงเป็นกราฟ รวมข้อเท็จจริงที่ล้าสมัย ตำรารายงานว่าบน LOCOMO ดีกว่า baseline ของ OpenAI 26% เชิงสัมพัทธ์ และลด token ได้มากกว่า 90% เทียบกับใส่บทสนทนาทั้งหมด
  • Sleep-time compute: ใช้เวลาว่างคาดคำถามและคิดเตรียมไว้ ลดการคำนวณตอนตอบราว 5 เท่า
  • A-MEM: โน้ตแบบ Zettelkasten ที่มีคำสำคัญ ป้าย และลิงก์ โน้ตใหม่ปรับโน้ตเก่าได้ (Roitman 2026, หมวด 17.11)

output ของ model ทุกอันในคลิปมาจากการรันจริง เวลาของความจำใน Lab 1 เป็นเวลาจำลอง (“เมื่อวาน”, “สองปีก่อน”) ผลที่ผู้เรียนรันเองอาจต่างไป โดยเฉพาะ Lab 3 ที่ model เลือกเองว่าจะบันทึกอะไร (memory recall ระหว่าง 0.5 ถึง 0.75 ในรอบที่เราลอง) ส่วนที่ 8 ของ Lab 2 รันโค้ดที่ model เขียนด้วย exec ทำได้ในการทดลองนี้ ระบบจริงต้องรันใน sandbox

คำถามทบทวน

  1. ยกตัวอย่างความจำทั้งสี่ชนิดของ research assistant ที่ช่วยคุณทำรายงาน
  2. ทำไมการกันซ้ำด้วยเกณฑ์ cosine 0.95 จึงพลาดใน Lab 1 และ Lab 2 แก้ได้อย่างไร
  3. ถ้าตั้ง decay_rate ให้จางเร็วมาก จะเกิดอะไรกับความจำที่สำคัญแต่เก่า
  4. ทำไมตำราให้เก็บวันศุกร์ไว้เป็นประวัติ แทนการเขียนทับ
  5. บทเรียนจากการทบทวนควรเก็บเป็นความจำชนิดไหน เพราะอะไร
  6. ใน Lab 3 ทำไมการให้ model เขียนความจำเองจึงได้ memory recall ต่ำกว่าการดึงอัตโนมัติ และต้องแลกกับอะไร
  7. ผู้ใช้ขอให้ลืมข้อมูลหนึ่ง ใน LangGraph คุณต้องลบที่ไหนบ้าง
  8. ออกแบบคำถามทดสอบ abstention หนึ่งข้อสำหรับ agent ของคุณ
