วัตถุประสงค์การเรียนรู้

เมื่อจบตอนนี้ ผู้เรียนจะสามารถ

  1. แปลงคำถามก่อนค้น (HyDE, step-back, multi-query, RAG-Fusion) และอธิบายได้ว่าทำไมจึงช่วย
  2. อธิบายว่าทำไม cross-encoder ใช้จัดลำดับชิ้นที่ค้นมาแล้วได้ แต่ใช้ค้นรอบแรกไม่ได้
  3. อธิบายว่า Self-RAG, CRAG, Adaptive RAG และ Graph RAG เปลี่ยนสายงาน RAG ตรงไหน
  4. บอกได้ว่าคำถามแบบไหนที่ RAG แบบตายตัวตอบไม่ได้ และอธิบาย agentic RAG ในฐานะลำดับของการตัดสินใจ
  5. สร้าง router และวงวน plan → retrieve → evaluate → generate ที่มีเพดานรอบ ทั้งเขียนเองและด้วย LangGraph
  6. วัดการค้นด้วย Recall@K, MRR และ NDCG วัดคำตอบด้วย faithfulness และ answer relevance และบอกได้ว่าแต่ละตัววัดมองไม่เห็นอะไร
  7. บอกความล้มเหลวหกแบบของ RAG ตามตำรา

คำถามที่ยังค้นไม่เจอ

ใน EP10 มีคำถามข้อหนึ่งที่พลาดทุกวิธี: บท RAG ในตำรา The Hitchhiker’s Guide to Agentic AI ของ Roitman ใช้อุปมาอะไรอธิบาย RAG พอมีชื่อผู้เขียนและชื่อตำราอยู่ในคำถาม ชิ้นบัตรห้องสมุดก็ไปอยู่อันดับ 8 ด้วย dense, อันดับ 5 ด้วย hybrid และอันดับ 17 ด้วย parent-child ตอนนี้เราลองสองทาง คือแปลงคำถามก่อนค้น และให้ agent ตัดสินใจเองว่าจะค้นอะไร ค้นที่ไหน และพอหรือยัง แล้วปิดด้วยคำถามสำคัญ: จะวัดอย่างไรว่า RAG ดีขึ้นจริง

ก่อนค้น: แปลงคำถาม

คำถามของผู้ใช้มักกำกวม สั้นเกินไป หรือใช้คำต่างจากในเอกสาร (Roitman 2026, หมวด 16.5.1)

  • HyDE: ให้ model ร่างคำตอบสมมุติขึ้นมา แล้วเอาร่างนั้นไปทำ embedding แทนคำถาม ร่างอาจผิดได้ เพราะเราใช้มันแค่ค้น ไม่ได้ใช้ตอบ ร่างเขียนด้วยภาษาแบบเดียวกับเอกสาร จึงอยู่ใกล้ชิ้นที่ถูกกว่า (สมการ 16.20)
  • Step-back: ถามคำถามที่กว้างกว่าก่อน เช่น ถามจุดเดือดของเอทานอลที่ 2 บรรยากาศ ก็ค้นเพิ่มว่าอะไรมีผลต่อจุดเดือดของของเหลว
  • Multi-query: เขียนคำถามใหม่หลายแบบ ค้นทุกแบบ แล้วรวมผล
  • RAG-Fusion: multi-query รวมคำถามเดิมด้วย แล้วรวมรายการอันดับทั้งหมดด้วย RRF (Listing 16.8) สูตรเดียวกับ EP10 Lab 2 ชิ้นที่ติดอันดับดีในหลายคำถามจะขึ้นมาบนสุด

ใน Lab 1 ร่างของ HyDE บอกว่าตำราใช้ “การสอบแบบเปิดตำรา” ซึ่งผิด แต่ค้นด้วยร่างนั้นกลับได้ชิ้นบัตรห้องสมุดที่อันดับ 1 ส่วน multi-query แบบธรรมดายังคงชื่อตำราไว้ในทุกคำถามย่อย (อันดับ 12, 13 และ 9 รวมแล้ว 9) พอสั่งให้ตัดชื่อตำราและชื่อผู้เขียนออก ผลรวมได้อันดับ 1

หลังค้น: re-rank และบีบ context

retriever ใน EP10 แปลงคำถามและเอกสารแยกกัน embedding ของเอกสารจึงคำนวณไว้ล่วงหน้าได้ และค้นได้เร็ว ส่วน cross-encoder อ่านคำถามกับเอกสารพร้อมกันในรอบเดียว แม่นกว่ามากแต่ช้า และใช้ค้นรอบแรกไม่ได้ เพราะไม่มีอะไรให้เก็บไว้ล่วงหน้า จึงใช้จัดลำดับใหม่เฉพาะชิ้นที่ค้นมาแล้ว ปกติ 20 ถึง 100 ชิ้น (Roitman 2026, หมวด 16.5.2) เหมือนรับสมัครงาน คัดเรซูเม่จากคำสำคัญก่อน แล้วค่อยเรียกห้าคนมาสัมภาษณ์จริง จากนั้น contextual compression ตัดแต่ละชิ้นให้เหลือเฉพาะส่วนที่ตอบคำถาม

ใน Lab 1 cross-encoder ให้ชิ้นบัตรห้องสมุดอยู่อันดับ 1 คะแนน 0.996 ชิ้นถัดไปได้ 0.50 วัด hit@3 บนคำถามทดสอบ 20 ข้อ: dense 12 · HyDE 16 · RAG-Fusion 14 · re-rank 18 · HyDE + re-rank 19

RAG ที่ตรวจตัวเอง และอีกสองแบบ

  • Self-RAG ฝึก model ตัวเดียวให้ตัดสินใจเองว่าจะค้นไหม ค้นมาแล้วเกี่ยวไหม คำตอบมีหลักฐานไหม และมีประโยชน์ไหม ผ่าน token พิเศษสี่ตัวที่เรียนรู้ระหว่างการฝึก
  • CRAG ไม่ฝึก model ใหม่ แต่เพิ่มตัวประเมินที่ให้คะแนนเอกสารแต่ละชิ้นว่า correct, ambiguous หรือ incorrect ถ้ามีบางชิ้นถูก ก็ตัดประโยคที่ไม่เกี่ยวออกแล้วตอบจากที่เหลือ ถ้าทุกชิ้นผิดหรือกำกวม ก็ไปค้นจากเว็บแทน
  • Adaptive RAG แยกคำถามตามความยากด้วยตัวจำแนกขนาดเล็ก: ไม่ต้องค้น ค้นครั้งเดียว หรือค้นหลายรอบ
  • Graph RAG ดึง entity และความสัมพันธ์ออกมาเป็น graph หากลุ่มในนั้น แล้วสรุปแต่ละกลุ่ม เก่งกับคำถามภาพรวม (ธีมหลักของคลัง) แต่สร้างแพง คำถามเฉพาะจุดยังใช้ RAG ปกติดีกว่า

Agentic RAG

RAG แบบตายตัวค้นครั้งเดียวแล้วตอบ ตำรายกจุดที่มันพังไว้ ได้แก่ คำถาม multi-hop (“ใครก่อตั้งบริษัทที่ซื้อคู่แข่งหลักของ OpenAI ในปี 2023”), คำถามกำกวม, คำถามย่อยที่ต้องใช้คลังความรู้ต่างกัน และการค้นครั้งแรกที่เผยว่าต้องค้นด้วยคำถามอื่น (Roitman 2026, หมวด 16.7) Agentic RAG มองการค้นเป็นลำดับของการตัดสินใจ: state คือคำถามกับเอกสารที่ค้นได้แล้ว action คือค้น คิด ตอบ หรือหยุด และรางวัลคือคำตอบที่ถูก เหมือน ReAct ใน EP05 แต่เครื่องมือหลักคือการค้น

เลือกแหล่งความรู้

ตำรายังแนะนำให้มีแหล่งสำรอง ค้นหลายแหล่งพร้อมกันแล้วรวมด้วย RRF และบันทึกทุกการเลือกพร้อมเหตุผล

วงวน

ตัวนับรอบกันไม่ให้ agent ค้นวนไม่รู้จบ เหมือน LoopGuard ใน EP08 ตำราเขียนวงวนนี้ด้วย LangGraph (Listing 16.10)

ใน Lab 2 เราเขียนวงวนนี้ด้วย Python ล้วน มีแหล่งความรู้สามแบบ คือ BM25, embedding และสารบัญของตำรา คำถามสองส่วนใช้ 11 call คำถาม “PLAID ย่อมาจากอะไร” ซึ่งตำราไม่เคยบอก วน 3 รอบแล้วตอบว่าเอกสารไม่มีข้อมูล ส่วนคำถามยาว: สารบัญพลาด grader ไม่ให้ผ่าน รอบ 2 ลอง vector แล้วเจอบัตรห้องสมุด grader แบบ CRAG ของเราให้ชิ้น top-3 จาก embedding ของคำถามนี้เป็น incorrect ทั้งสามชิ้น

ใน Lab 4 agent ตัวเดิมด้วย LangGraph เดินเส้นทางเดียวกัน ถ้าเขียนแบบในตำรา node ที่คืน {**state, ...} ทำให้ reducer operator.add เพิ่มเอกสารซ้ำ ได้ 4 เอกสาร [301, 357, 301, 357] แทน 2 ให้คืนเฉพาะ key ที่เปลี่ยน และเมื่อตั้งเพดานรอบสูงเกินไป recursion_limit หยุด graph ด้วย GraphRecursionError

Search-R1

ทุกอย่างข้างบนควบคุมด้วย prompt Search-R1 ฝึก model ด้วย reinforcement learning ให้ตัดสินใจเองว่าเมื่อไรควรค้น ค้นอะไร และกี่ครั้ง รางวัลคือความถูกของคำตอบสุดท้าย (Table 16.4) ตำรารายงานว่า model ขนาด 7B แม่นกว่า RAG ที่ค้นครั้งเดียวราว 15–20% ซีรีส์นี้ไม่ได้ฝึก model เราจึงใช้ agentic RAG ที่สั่งด้วย prompt

นอกตำรา: ให้ agent ไล่สารบัญ

ส่วนนี้ไม่อยู่ในตำรา

เวลาหาเรื่องบัตรห้องสมุดในหนังสือหกร้อยหน้า เราไม่ได้เทียบทุกหน้า เราเปิดสารบัญ เลือกบท เลือกหัวข้อ ถ้าไม่ใช่ก็ย้อนกลับ MemWalker (Chen และคณะ 2023) สร้าง tree ของบทสรุป แล้วให้ model เดินจากบนลงล่าง ที่แต่ละ node เลือกเปิดลูก ย้อนขึ้น หรือตอบ RAPTOR (Sarthi และคณะ 2024) สร้าง tree ของบทสรุปเหมือนกัน แต่ค้นด้วย embedding ส่วนโปรเจกต์ open source PageIndex ไล่ tree แบบสารบัญโดยไม่ใช้ embedding เลย MemWalker รายงานว่าวิธีนี้ต้องใช้ model ใหญ่ (ราว 70B)

ใน Lab 2 Gemma 4 26B ไล่สารบัญ 157 หัวข้อของตำรา จากรากไปถึง Framework Comparison (หน้า 359–360) ใน 3 ก้าว โดยไม่ใช้ embedding

วัดผล RAG

ความผิดพลาดเริ่มได้ทุกขั้นและสะสมต่อกัน ตำราจึงวัดสามระดับ คือการค้น คำตอบ และทั้งระบบ และเตือนว่าอย่าปรับแค่ระดับเดียว เช่น K ใหญ่ทำให้ recall สูง แต่ใส่ชิ้นที่แทบไม่เกี่ยวเต็ม context (Roitman 2026, หมวด 16.8)

  • Recall@K: สัดส่วนของชิ้นที่ถูกที่อยู่ใน K อันดับแรก (สมการ 16.22)
  • MRR: ค่าเฉลี่ยของ 1 / อันดับของชิ้นที่ถูกชิ้นแรก (สมการ 16.24) อันดับ 1, อันดับ 3 และไม่เจอ: (1 + 1/3 + 0) / 3 ≈ 0.44
  • NDCG@K: ชิ้นที่ถูกยิ่งอยู่สูงยิ่งได้คะแนนมาก (สมการ 16.25)
  • Faithfulness: claim ที่มีหลักฐาน ÷ claim ทั้งหมด ให้ LLM เป็นผู้ตัดสิน (สมการ 16.26) สาม claim มีหลักฐานสอง: 2/3
  • Answer relevance: สร้างคำถามย้อนกลับจากคำตอบ แล้วเทียบกับคำถามเดิม (สมการ 16.27)

re-rank ดัน MRR จากราว 0.5 เป็นราว 0.8 แต่ recall แทบไม่ขยับ เพราะมันจัดลำดับยี่สิบชิ้นเดิม ไม่ได้หาชิ้นใหม่

ใน Lab 3 คำตอบที่ไม่มี RAG ผิด แต่ยังได้ 0.78 claim ที่เป็นแกนของคำตอบไม่มีหลักฐาน แต่มีน้ำหนักเท่ากับ claim ทั่วไปข้ออื่น answer relevance แยกสามคำตอบไม่ออก มีแค่ correctness เทียบกับคำตอบอ้างอิงที่คนเขียนไว้ที่แยกได้ และให้คำตอบแบบ re-rank เป็นคำตอบที่ถูก

ความล้มเหลวหกแบบ และระบบจริง

  1. Retrieval miss: เอกสารอยู่ในคลัง แต่ค้นไม่เจอ (คำถามยาวของเรา)
  2. Context poisoning: เอกสารที่ค้นมาผิดหรือขัดกันเอง คำตอบเลยผิดตาม
  3. Lost in the middle: model สนใจต้นและท้ายของ context ยาวมากกว่าตรงกลาง
  4. Over-retrieval: ชิ้นเยอะเกินไป สิ่งที่เกี่ยวจริงถูกกลบ และแพงขึ้น
  5. Hallucination ทั้งที่มีเอกสาร: model ไม่สนเอกสาร ตอบจากความจำ
  6. Citation fabrication: อ้างเอกสารที่ไม่ได้พูดแบบนั้น

สำหรับระบบจริง ตำราบอกว่า embedding model คือตัวเลือกที่มีผลมากที่สุด เพราะกำหนดเพดานคุณภาพของการค้น และยังเปรียบเทียบ vector database บอกวิธีลด latency (กรองด้วย metadata ก่อน ค้นหลายแหล่งพร้อมกัน) และแนะนำให้อัปเดตชิ้นของเอกสารที่เปลี่ยนพร้อมเลขเวอร์ชัน แทนการสร้าง index ใหม่ทั้งหมด (Roitman 2026, หมวด 16.9)
