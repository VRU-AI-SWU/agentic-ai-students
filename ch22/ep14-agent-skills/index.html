วัตถุประสงค์การเรียนรู้

เมื่อจบตอนนี้ ผู้เรียนจะสามารถ

  1. อธิบายว่า skill ต่างจาก tool และ agent อย่างไร และบอกห้าส่วนของ skill
  2. เทียบสามวิธีโหลด skill: static, dynamic discovery ด้วย skill router และ hierarchical composition
  3. เขียน skill เป็นโฟลเดอร์ SKILL.md แล้วโหลด เปิดใช้ และตรวจกฎด้วยโค้ด
  4. เขียน router ที่เลือก skill จากชื่อและคำอธิบาย และอธิบายว่าทำไมคำอธิบายที่คลุมเครือทำให้พลาด
  5. คลี่กราฟ dependency ของ skill พร้อมตรวจเวอร์ชัน และสร้างคลัง skill ที่เรียนรู้เองแบบ Voyager
  6. ใช้ skill ชุดเดิมกับ deepagents และอธิบาย progressive disclosure
  7. ตัดสินว่าเมื่อไรควรใช้ skill และเมื่อไรควร fine-tune

มี tool ครบ แต่ยังทำงานไม่เป็น

หลัง EP13 agent ของเราต่อ tool ได้แทบทุกอย่าง แต่สั่งงานจริง “สรุป paper สามเรื่องเรื่องความจำของ agent ให้นักศึกษาปีหนึ่ง” agent ต้องรู้เองว่าใช้ tool ไหน ทำอะไรก่อนหลัง เขียนหน้าตาแบบไหน และตรวจอะไรก่อนส่ง เหมือนเด็กฝึกงานวันแรกที่ได้กล่องเครื่องมือครบ แต่ไม่มีใครบอกวิธีทำงาน ถ้าเขียนวิธีทำทุกงานลง system prompt ก็ยาวเป็นสิบหน้า และถูกส่งไปทุกครั้ง skill คือวิธีห่อความรู้ว่าทำงานหนึ่งอย่างไร ให้ agent หยิบมาใช้เมื่อต้องการ

Skill คืออะไร: ห้าส่วนในหนึ่งชุด

ตำรานิยาม skill ว่าเป็นหน่วยความสามารถที่ครบในตัวเอง ทำให้ agent เชี่ยวชาญงานหนึ่งงาน (Roitman 2026, หมวด 22.1) skill หนึ่งตัวมีห้าส่วน

ความคิดนี้ดังจาก Voyager ซึ่ง agent ใน Minecraft สะสม skill เป็นโค้ดที่ตรวจแล้วว่าใช้ได้ และเก็บไว้ใช้ซ้ำ ที่สำคัญคือ skill ใส่ ถอด หรือสลับได้โดยไม่ต้องฝึก model ใหม่

ตำราสรุปสามคำนี้ด้วยภาพเดียว: tool คือค้อน · skill คือการรู้ว่าจะขึ้นโครงบ้านอย่างไร · agent คือช่างไม้ที่เลือกว่าจะใช้ skill ไหน

ใน Lab 1 งานเดิมสองรอบ ไม่มี skill ได้ markdown 621 คำ ไม่มีการอ้างอิง และไม่ผ่านตัวตรวจ มี skill paper-summary ได้ JSON สามประโยค ทุกประโยคอ้าง paper ที่เปิดอ่านจริง ผ่านทุกข้อ แลกกับ token ขาเข้าที่เพิ่มจาก 212 เป็น 463 ในทุกครั้งที่เรียก model

สามวิธีโหลด skill

ใน Lab 2 คลัง skill หกตัว ใส่ทุกตัวแบบ static งานสรุปงานเดียวใช้ token ขาเข้า 4,841 ให้ router เลือกจากชื่อกับคำอธิบาย ใช้ 2,322 (รวมการเรียก router แล้ว) skill ที่คำอธิบายบอกแค่ “Formats text.” ทำให้ router ตอบ none กับคำถามเรื่องการอ้างอิง แก้คำอธิบายบรรทัดเดียวก็เลือกถูก และสิทธิ์ที่กรองก่อนถึง router ทำให้นักศึกษาไม่เห็น skill ให้คะแนนของอาจารย์เลย

ใน Lab 3 ตัวคลี่กราฟที่เราเขียนเองได้ลำดับ paper-summary → citation-format → literature-review และหยุดตั้งแต่ก่อนเรียก model เมื่อ meeting-notes หายไป หรือเมื่อต้องการ citation-format 2.x แต่คลังมี 1.1.0 · literature-review ไม่มี tool ของตัวเอง แต่ได้ย่อหน้าที่อ้างอิง และรายการ APA จาก skill ย่อย

กรณีศึกษา Anthropic: augmented LLM กับลูปง่ายๆ

ตำรายกแนวคิดของ Anthropic (Roitman 2026, หมวด 22.3) เริ่มจากทางที่ง่ายที่สุดก่อน แยก workflow ที่เราวางทาง ออกจาก agent ที่ model ตัดสินใจเอง (ดู EP04 กับ pattern ทั้งห้า ซึ่งตำราบอกว่าใช้เป็นแม่แบบของ skill ได้) และหน่วยที่เล็กที่สุดไม่ใช่ model เปล่า แต่เป็น augmented LLM = model + retrieval + tools + memory ซึ่งก็คือ model ที่ติด skill แล้ว

ข้อสังเกตสำคัญ: agent ที่ได้ผลดีที่สุดไม่ใช่ตัวที่ซับซ้อนที่สุด แต่เป็นลูปง่ายๆ กับ tool ที่ดี ความฉลาดมาจากความสามารถของ model คุณภาพของคำอธิบาย tool และความชัดเจนของการบอกงาน สองข้อหลังคือสิ่งที่ skill จัดให้

ห้าคำแนะนำในการออกแบบ: ทำลูปให้ง่าย · ลงแรงกับคำอธิบาย tool · บังคับ structured output · เตรียมทางกู้เมื่อผิด · จำกัดขอบเขตของแต่ละ skill (skill ที่พยายามทำทุกอย่าง จะทำอะไรได้ไม่ดีสักอย่าง)

วงจรชีวิตของ skill หกขั้น

ค้นพบว่ามี skill อะไร → เลือกตามคำขอ → เปิดใช้ (ใส่คำสั่ง tool และความรู้เข้า context) → ทำงาน → ปิดใช้ (เอาออกให้มีที่ว่าง) → เรียนรู้ (ปรับตัวอย่างหรือการเลือก) (Roitman 2026, หมวด 22.4) เหมือนเชฟหยิบการ์ดสูตรมาวางบนโต๊ะ ทำเสร็จเก็บคืน และจดโน้ตลงการ์ด

ใน Lab 3 คลังที่เรียนรู้เองแบบ Voyager: เมื่อไม่มี skill ที่เหมาะ agent เขียน skill เป็นโค้ดพร้อม test รัน test แล้วเก็บ คำถามถัดไปใช้ซ้ำ จากคลังว่างได้สอง skill (papers-per-year-count, sort-papers-by-year) ที่ใช้ซ้ำไปอีกสองครั้ง ข้อควรระวัง: exec รันโค้ดที่ model เขียน ทำได้เฉพาะใน lab ระบบจริงต้องใช้ sandbox

Manifest, คลัง และร้านค้า skill

เมื่อ skill มีมาก ต้องมีระบบรองรับห้าอย่าง (Roitman 2026, หมวด 22.5): manifest คำอธิบายแบบมีโครงสร้าง (ชื่อ ความสามารถ tool ที่ต้องใช้ input schema) · เวอร์ชัน ตรึงไว้ให้ผลซ้ำได้ · dependency ทั้ง MCP server, API key และ skill อื่น · สิทธิ์ ไม่ใช่ทุก agent ควรได้ทุก skill · ร้านค้า เผยแพร่และติดตั้ง skill เหมือน pip ตำราบอกชัดว่ายังไม่มี schema มาตรฐานของวงการสำหรับ manifest — SKILL.md ใน lab เป็นรูปแบบที่หลายเครื่องมือใช้กัน

Skill vs fine-tuning

สองทางนี้เสริมกัน fine-tuning ให้ความสามารถพื้นฐาน (ทำตามคำสั่ง รูปแบบการเรียก tool การคิด) skill ใส่ความเชี่ยวชาญเฉพาะงานไว้ด้านบนตอนใช้งาน (Roitman 2026, หมวด 22.6)

เขียนเอง vs deepagents

ใน Lab 4 skill ชุดเดิมกับ deepagents ของ LangChain: SkillsMiddleware ค้นพบ skill จากโฟลเดอร์ ไม่มี router แยก model ตัวที่ทำงานเลือกเอง แล้วเปิด SKILL.md ด้วย read_file การเรียกครั้งแรกเห็นแค่ read_file หลังอ่าน skill แล้ว search_papers กับ get_paper จึงโผล่ขึ้นมา (progressive disclosure, metadata.include_tools) สิทธิ์ทำด้วย sources คนละชุดต่อบทบาท อาจารย์เปิด rubric แล้วให้ 1/3 · แลกกับ token: งานสรุปหนึ่งงานใช้ 5,937 เทียบกับราว 2,300 ของ router ที่เราเขียนเอง และตัวคลี่กราฟกับคลังที่เรียนรู้ไม่มีในตัว ตอนลอง create_deep_agent ที่มี tool มาก Gemma ส่งงานให้ subagent โดยไม่เปิด skill เราจึงประกอบเองด้วย create_agent กับ middleware สองตัว

คำถามทบทวน

  1. skill ต่างจาก tool อย่างไร ยกตัวอย่างห้าส่วนของ skill ที่คุณอยากเขียน
  2. ถ้ามีคลัง skill 200 ตัว คุณจะเลือก static หรือ dynamic เพราะอะไร และต้องระวังอะไร
  3. ใน Lab 2 ทำไม router จึงพลาดกับ formatter และแก้ด้วยอะไร โดยไม่แตะโค้ดของ router เลย
  4. ทำไมตัวคลี่กราฟควรหยุดตั้งแต่ก่อนเรียก model เมื่อเวอร์ชันไม่ตรง
  5. ใน Lab 3 test ของ skill ที่ model เขียน เป็นแค่การตรวจขั้นแรก เพราะอะไร และ Voyager ตรวจด้วยอะไร
  6. progressive disclosure ใน deepagents ช่วยเรื่องอะไร และแลกกับอะไร
  7. งานแบบไหนที่คุณจะเลือก fine-tune แทนการเขียน skill
