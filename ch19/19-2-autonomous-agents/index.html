วัตถุประสงค์การเรียนรู้

เมื่อจบ module นี้ ผู้เรียนจะสามารถ

  1. อธิบายความแตกต่างระหว่าง workflow และ autonomous agent
  2. อธิบาย ReAct loop และองค์ประกอบที่ harness ต้องมี 4 อย่าง

  5. เลือก tool-use pattern ที่เหมาะกับงาน และเขียนโค้ดแต่ละ pattern ได้

จาก Workflow สู่ Agent

ใน §19.1 เราเรียน workflow pattern ซึ่งโปรแกรม (ไม่ใช่ model) เป็นผู้กำหนดลำดับการทำงาน ส่วน autonomous agent pattern ใน section นี้ ให้ LLM เป็นผู้ควบคุม execution flow เอง ว่าจะเรียก tool ใด เมื่อใด และจะหยุดเมื่อใด (Roitman 2026, หมวด 19.2)

สำคัญเริ่มจาก workflow ก่อนเสมอ

ตำราแนะนำให้ใช้ agent เฉพาะเมื่องานต้องการ dynamic routing หรือการสำรวจแบบปลายเปิดจริงๆ เท่านั้น

ReAct (Reason + Act)

ReAct เป็น pattern พื้นฐานของ agent เกือบทุกตัว LLM สลับกันระหว่าง Thought (คิดว่าจะทำอะไร), Action (เรียก tool) และ Observation (อ่านผลลัพธ์) วนไปจนได้คำตอบสุดท้าย

\[ \text{Thought}_t \rightarrow \text{Action}_t \rightarrow \text{Observation}_t \rightarrow \text{Thought}_{t+1} \rightarrow \cdots \tag{1.1}\]

Harness ที่ครอบ ReAct loop (รูปที่ 1.1) ต้องมี 4 องค์ประกอบ

  1. Scratchpad — ขั้น Thought ถูกบันทึกไว้ แต่ไม่แสดงให้ผู้ใช้
  2. Tool parsing — ดึง tool call ที่มีโครงสร้างออกจาก output ของ model
  3. Max iterations — จำกัดจำนวนรอบเสมอ (โดยทั่วไป 10–25 รอบ)
  4. Termination — จบเมื่อ model ส่ง action พิเศษ เช่น final_answer หรือเมื่อไม่มี tool call

ใน notebook: ฟังก์ชัน react_agent() มีคอมเมนต์ ①–④ ตรงกับ 4 ข้อนี้

Planning Agents

ReAct ตัดสินใจทีละก้าว ซึ่งอาจหลงทางในงานยาว planning agent จึงสร้าง plan ที่ชัดเจนก่อนลงมือ และแก้ plan ระหว่างทางได้ บทที่ 18 เรียกแนวทางนี้ว่า Plan-and-Execute ซึ่งมี 3 ช่วง คือ planning phase, execution phase (อาจใช้ model ที่ถูกกว่า) และ plan revision

\[ \text{Plan} = \text{Planner}(q), \qquad \text{Result} = \prod_{i=1}^{|\text{Plan}|} \text{Executor}(\text{Plan}[i], \text{context}_i) \tag{1.2}\]

ตัวอย่าง: รายงานเปรียบเทียบ transformer สำหรับ time-series

ผู้ใช้สั่ง “Write a 2-page report comparing transformer architectures for time-series forecasting.” Planner สร้าง plan 6 ขั้น แต่ละขั้นมี deps ระบุขั้นที่ต้องเสร็จก่อน ทำให้ plan เป็น DAG (Directed Acyclic Graph) ดัง รูปที่ 1.2

Harness ติดตาม dependency และ execute เฉพาะขั้นที่ขั้นก่อนหน้าเสร็จครบแล้ว

Adaptive replanning

หลังขั้นที่ 1 การค้นหาพบ paper ที่เกี่ยวข้องเพียง 3 ฉบับ agent จึง replan โดยเพิ่ม sub-step ขยายการค้นหาไปยังโดเมนใกล้เคียง (เช่น PatchTST, iTransformer) แล้วทำต่อจากขั้นที่ 2 ด้วยข้อมูลที่มากขึ้น

หมายเหตุKey insight

Plan คือ living document — ให้โครงสร้าง แต่ปรับตามสิ่งที่สังเกตได้

Reflection และ Self-Critique

Agent หยุดประเมินเส้นทางของตัวเองใน 3 ระดับ

  1. Output validation — “ถูกไหม ลืมอะไรไหม”
  2. Trajectory review — ย้อนดู k ขั้นล่าสุด หาข้อผิดพลาดหรือความสิ้นเปลือง
  3. Strategy revision — “เรากำลังแก้ปัญหาถูกข้ออยู่หรือเปล่า”

Reflexion

Reflexion เก็บ reflection memory ไว้ หลังทำพลาดแต่ละครั้ง agent เขียนบทเรียนเป็นภาษาธรรมชาติ (เช่น “พลาดเพราะไม่ได้เช็ค edge case”) แล้วใส่บทเรียนเหล่านี้ใน prompt รอบถัดไป ทำให้เรียนรู้ข้าม episode ได้ โดยไม่ต้องอัปเดต weight

Tool-Use Patterns

ข้อควรจำ

  • Multi-tool ลด latency ได้มาก แต่ tool ต้อง เป็นอิสระต่อกัน และต้องส่ง tool result ทั้งหมดกลับใน message เดียว
  • Sequential harness ต้องดูแล context ที่โตขึ้น และอาจต้องสรุปผลระหว่างทาง
  • Nested parent agent มองเห็น sub-agent เป็น black-box function
  • Fallback จัดการที่ระดับ harness model ไม่จำเป็นต้องรู้

เลือก pattern ไหนดี

เริ่มจาก pattern ที่ง่ายที่สุด แล้วขยับขึ้นเมื่อ pattern ที่ง่ายกว่าใช้ไม่ได้จริงเท่านั้น และ pattern ต่างๆ ประกอบกันได้

คำถามทบทวน

  1. ทำไมตำราจึงแนะนำให้เริ่มจาก workflow ก่อน agent
  2. ถ้าไม่มี max iterations ใน ReAct loop จะเกิดปัญหาอะไร
  3. จาก รูปที่ 1.2 ขั้นใดบ้างที่รันพร้อมกันได้ เพราะอะไร
  4. Reflexion ต่างจากการ fine-tune model อย่างไร
  5. ทำไม multi-tool pattern จึงใช้ไม่ได้กับ tool ที่ต้องใช้ผลของอีก tool
