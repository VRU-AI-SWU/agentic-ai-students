Lab walkthrough · EP06 Design Principles and Choosing a Pattern

หมายเหตุวิธีใช้หน้านี้

หน้านี้คือ notebook เฉลยของ lab นี้ทีละ cell พร้อม output จากการรันจริงตอนอัดคลิป ไว้อ่านทวนก่อนหรือหลังลงมือ cell ที่มี ✏️ TODO แสดงโค้ดแบบใน starter notebook ส่วนเฉลยเต็มอยู่ในกล่อง ดูเฉลย ลองเขียนเองก่อนค่อยเปิด

▶ วิดีโอ · ✏️ Starter ใน Colab · ✅ เฉลยใน Colab · กลับไปหน้า EP06 Design Principles and Choosing a Pattern

model ตอบไม่เหมือนเดิมทุกครั้ง output ที่คุณรันเองจึงอาจต่างจากหน้านี้

§19.4 บอกให้ใช้ตาราง 19.3 เป็น decision matrix: เริ่มจากแถวบนสุด (ง่ายที่สุด) แล้วลงมาเมื่อแบบที่ง่ายกว่าพังให้เห็นจริงๆ เท่านั้น และให้ดูสามเรื่อง: โครงสร้างงานคาดเดาได้แค่ไหน · จ่าย LLM call ได้กี่ครั้ง (เวลา + เงิน) · คุณภาพต้องอาศัยการทำซ้ำไหม

สิ่งที่จะได้เรียน

  1. ตัววัด: นับ LLM call, tool call, token, ค่าใช้จ่าย และเวลา ของแต่ละ pattern
  2. pattern แถวบน: prompt chaining — ขั้นตอนตายตัว 2 LLM call
  3. pattern แถวกลาง: ReAct — model เลือกเองว่าจะเรียก tool อะไร กี่ครั้ง
  4. งาน A: chain พอไหม? · งาน B: chain พังจริงไหม? แล้วลงไป ReAct คุ้มไหม

คลัง paper (ชื่อ ปี เป็นของจริง) สรุปเนื้อหา และ คะแนนจากผู้เรียนเป็นข้อมูลจำลองที่เขียนขึ้นเพื่อการสอน ส่วนการเรียก tool คำตอบของ model และตัวเลขที่วัดได้ทั้งหมดมาจากการรันจริง

    STATS.update(calls=0, tools=0, tokens_in=0, tokens_out=0)

def react(question, max_steps=8):
    messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": question}]
    for step in range(max_steps):
        msg = llm(messages=messages, tools=TOOLS)
        messages.append(msg.model_dump(exclude_none=True))
        if not msg.tool_calls:

        for call in msg.tool_calls:
            result = run_tool(call.function.name, json.loads(call.function.arguments))
            STATS["tools"] += 1
            messages.append({"role": "tool", "tool_call_id": call.id,
                             "content": json.dumps(result, ensure_ascii=False)})
    return "หยุด: ครบจำนวนรอบ"
